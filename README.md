## قابلیت‌ها

- فروش VLESS، L2TP و OpenVPN با پرداخت کارت‌به‌کارت و تأیید دستی رسید توسط مدیر
- دریافت خودکار فهرست تمام Inboundهای پنل از API و نمایش نام، شناسه، پروتکل، پورت و وضعیت آن‌ها در پنل مدیریت تلگرام
- ساخت سرویس قیمت‌گذاری حجمی متصل به یک Inbound مشخص؛ تنظیم مدت، قیمت هر گیگ در ماه، حداقل و حداکثر حجم و فعال/غیرفعال‌کردن سرویس از منوی گرافیکی
- ساخت پلن ثابت متصل به Inbound مشخص، شامل حجم دلخواه یا نامحدود (صفر گیگ)، مدت و قیمت؛ امکان تغییر Inbound پلن از پنل مدیر
- تغییر Inbound متصل به هر سرویس از پنل مدیریت
- برای هر پلن OpenVPN، مدیر TCP یا UDP را از منوی تلگرام تعیین می‌کند؛ ربات پس از ساخت حساب، فایل واقعی `.ovpn` را از API همان Inbound در همان پنل دانلود و همراه نام کاربری و رمز برای مشتری ارسال می‌کند. فایل‌های سرور داخل سورس یا مخزن GitHub قرار نمی‌گیرند.
- پیام خوش‌آمدگویی پیش‌فرض قابل ویرایش و ذخیره از پنل گرافیکی مدیر، بدون تغییر سورس
- پلن‌های آماده، حجم نامحدود، انتخاب نام کاربری، بررسی تکراری‌نبودن نام، حساب تست، تمدید، مشاهده حساب‌ها و سفارش‌ها، پشتیبانی و ابزارهای پایه مدیریت
- ذخیره رمزهای حساب با Fernet؛ تنظیمات حساس فقط در فایل `.env`
- مهاجرت خودکار ساختار دیتابیس قدیمی برای افزودن شناسه Inbound به سرویس‌های قیمت‌گذاری حجمی

## سازگاری و محدودیت‌های مهم

- ساخت خودکار حساب و تحویل اتصال در این نسخه برای VLESS، L2TP و OpenVPN (روی API سازگار vpn-ui) پیاده‌سازی شده است.
- قالب لینک VLESS برای transportهای رایج TCP/WS و TLS/Reality نوشته شده؛ transportهای دیگر و تفاوت forkها ممکن است به تطبیق نیاز داشته باشند.
- L2TP از پیاده‌سازی فعلی پنل استفاده می‌کند و باید روی همان نسخه پنل مقصد آزمایش شود.
- دریافت فهرست Inboundها از مسیر `GET /panel/api/inbounds/list` و جزئیات هر Inbound از `GET /panel/api/inbounds/get/:id` انجام می‌شود.
- پشتیبانی OpenVPN بر اساس API پروژه Sir-MmD/vpn-ui است: حساب با API استاندارد پنل ساخته می‌شود و فایل با `GET /panel/api/inbounds/:id/ovpn/:proto` دریافت می‌شود. forkهای دیگر ممکن است این مسیر را نداشته باشند؛ در آن صورت فروش OpenVPN باید تا افزودن adapter مناسب غیرفعال بماند.
- `DRY_RUN=true` پیش‌فرض است؛ در این حالت هیچ عملیات نوشتنی به پنل ارسال نمی‌شود و ساخت حساب واقعی انجام نخواهد شد. برای نصب تازه، مدیر باید پلن‌ها را از منوی تلگرام بسازد و Inbound را انتخاب کند؛ هیچ شناسه Inbound سرور خاصی پیش‌فرض نیست.
- این بسته به سرور یا تلگرام کاربر متصل نشده و آزمون end-to-end روی پنل مقصد انجام نشده است.

## نصب روی Ubuntu 22.04 / 24.04

```bash
unzip aminui-sales-bot-0.1.2.zip
cd aminui-sales-bot
sudo bash install.sh
sudo nano /opt/aminui-sales-bot/.env
```

مقادیر `BOT_TOKEN`, `ADMIN_IDS`, `VPNUI_BASE_URL`, `VPNUI_USERNAME`, `VPNUI_PASSWORD`, `VPN_PUBLIC_HOST`, `CARD_NUMBER` و `CARDHOLDER_NAME` را در `.env` تنظیم کنید. `VPNUI_BASE_URL` باید Base Path صحیح پنل را داشته باشد. کلید Fernet توسط installer ساخته می‌شود؛ حتماً از آن نسخه پشتیبان امن بگیرید.

پس از تنظیم:

```bash
sudo chmod 600 /opt/aminui-sales-bot/.env
sudo systemctl start aminui-sales-bot
sudo systemctl status aminui-sales-bot
journalctl -u aminui-sales-bot -f
```

## راهنمای پنل تلگرام

- از «مدیریت ربات ← مشاهده Inboundهای پنل» همه Inboundهای برگشتی از پنل را ببینید.
- از «مدیریت سرویس‌ها ← افزودن سرویس» یک Inbound فعال VLESS، L2TP یا OpenVPN انتخاب کنید و مدت، قیمت هر گیگ در ماه و بازه حجم را تعیین کنید.
- از صفحه همان سرویس می‌توانید Inbound متصل را عوض کنید یا قیمت، مدت، حداقل/حداکثر حجم و وضعیت فروش را تغییر دهید.
- از «مدیریت ربات ← متن خوش‌آمدگویی» متن `/start` را تغییر دهید. متن ذخیره‌شده در دیتابیس است و با restart باقی می‌ماند.
- برای OpenVPN پس از انتخاب Inbound، مدیر باید TCP یا UDP را مشخص کند. فایل از همان پنل و همان Inbound دریافت می‌شود؛ هیچ `.ovpn` اختصاصی در مخزن وجود ندارد.

## APIهای استفاده‌شده

- `GET /panel/api/inbounds/list`
- `GET /panel/api/inbounds/get/:id`
- `POST /panel/api/inbounds/addClient`
- `POST /panel/api/inbounds/updateClient/:clientId`
- `POST /panel/api/inbounds/:id/delClient/:clientId`
- `GET /panel/api/inbounds/:id/ovpn/:proto` (فایل خام پروفایل OpenVPN؛ `proto` برابر `tcp` یا `udp`)

مستندات مرجع: https://github.com/Sir-MmD/vpn-ui/blob/main/api-reference.md . این مرجع لزوماً با تمام forkها و buildها یکسان نیست.

## آزمون‌ها

پس از نصب وابستگی‌ها، آزمون‌ها را با دستور `python -m unittest discover -s tests -v` اجرا کنید. آزمون OpenVPN ساخت حساب، شناسه رمز عبور، انتخاب TCP/UDP، تمدید و دریافت فایل را با پاسخ‌های mock بررسی می‌کند؛ آزمون اتصال واقعی به سرور VPN-UI باید روی یک Inbound آزمایشی انجام شود.

## امنیت

- فایل `.env`، دیتابیس، کلید Fernet، فایل‌های `.ovpn` دریافت‌شده و اطلاعات کاربران را منتشر نکنید. فایل‌های پروفایل فقط هنگام تحویل از API همان پنل دریافت می‌شوند و بخشی از مخزن نیستند.
- TLS پنل را خاموش نکنید.
- فقط Telegram ID مدیران مورداعتماد را در `ADMIN_IDS` قرار دهید.
- از دیتابیس و کلید Fernet به‌صورت امن و جداگانه بکاپ بگیرید.
- اگر نتیجه عملیات نوشتن پنل مبهم شد، سفارش خودکار دوباره اجرا نمی‌شود؛ ابتدا وضعیت Inbound را بررسی کنید.
